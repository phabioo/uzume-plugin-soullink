# Architecture

Status: v0.9.0 (manifest `recap` block for the Uzume 0.22 run recap: catch, death as lost, badge, correction as note; new automatic run event `soullink.badge` {user, index, count} per new badge, deduplicated through the persisted own state and the events already in the run; "Demo data" tag in the panel header when pokemon-core reports `info().demo`); v0.8.3 (shows the run's randomizer from the optional `fb.run.current().randomizer` of Uzume 0.21: a fact line "Randomized · each person their own world · <preset>" in the run tab header and run board, a "Randomized" badge in the in-game panel, "own variant" next to people with `variant_kind` "own"; display only, no rule changes, seeds and settings never shown); v0.8.2 (save snapshot "before Gym N" through `fb.save.snapshot` (Uzume 0.20) when a gym leader battle starts: a trainer battle in which a foe reaches the level cap of the next gym, since pokemon-core marks no boss battles; once per gym and session, guarded for older apps without `fb.save`); v0.8.1 (icon cache keyed by icon_rev); v0.8.0 (Uzume design boards 5b, 5e, 5f: panel, HUD, run tab and corrections follow the boards as far as the fb.ui blocks allow); v0.7.1 (Uzume wording in texts and comments); v0.7.0 (plugin id uzume.soullink; v0.6.2: corrections shape detection, icon check; map from the game files or the game picture, full-screen default crop, "Game data" block with every key; place picker with every place, compact panel, run screen in the screen slot, detection from pokemon-core 0.3 / 0.3.1). Everything below is design against plugin API v1 as documented in `docs/guides/plugin-api.md` of the Uzume repository; open API items are listed at the end.

## Layout

- `src/`: Lua modules; the list is `src/modules.txt`. `src/main.lua` is the entry (package 1: loads the modules and logs).
  - `data/oras.lua`: place keys (`starter`, `loc:<location id>`, legacy `route-N`, `place:<text>`), `ZONES` (fallback zone table, empty), `COORDS` (positions per game id, empty), level caps, labels, game order.
  - `app/controller.lua` (wiring to `fb`), `app/sync.lua` (set/patch of UI slots), `app/icons.lua` (lazy creature icons from pokemon-core into the own cache), `app/maps.lua` (region map from the game picture or the game files, recorded route positions).
  - `ui/common.lua`, `panel.lua`, `hud.lua`, `tile.lua`, `screen.lua`, `corrections.lua`, `board.lua`: pure builders `ctx -> block tree`.
  - `model/util.lua`, `rules.lua`, `state.lua`, `detect.lua`, `snapshot.lua`, `events.lua`, `corrections.lua`, `view.lua`.
- `tools/bundle.lua`: generates the single `plugin/main.lua` (the sandbox has no `require`). `lua5.4 tools/bundle.lua` writes, `--check` fails when it is stale. A new module must be listed in `src/modules.txt`.
- `plugin/`: installable plugin: `manifest.json`, generated `main.lua` (committed, never edit), `i18n/en.json` (source) and `de.json`.
- `tests/`: `lua5.4 tests/run.lua` runs every `tests/test_*.lua` against synthetic data. Support: `support/fb_mock.lua` (fake `fb` with `fb.call`, `fb.run`, `fb.ui.open` unless `no_ui_open`), `support/fake_core.lua` (fake `pokemon.core` v0.3: areas, names, location, encounters with seq, battle, badges, species_info), `support/build.lua` (record, tracker, event log builders), `support/t.lua`.
- `tools/package.py`: builds and verifies `plugin/` as `<id>-<version>.uzplugin` (deterministic zip, copied from pokemon-core).
- CI (`.github/workflows/ci.yml`): `lua5.4 tools/bundle.lua --check`, `lua5.4 tests/run.lua`, package build and verify.
- Release (`.github/workflows/release.yml`): a tag `vX.Y.Z` (or a manual run with a tag; a new tag is created at the dispatch commit on `main`) checks bundle and tests, runs `tools/package.py --tag` (fails when the tag differs from the manifest version) and attaches the `.uzplugin` to the GitHub release. The package is unsigned.

The model is pure: it never reads `fb` (only `snapshot.from_core(fb)` calls `fb.call`). Game names (species, moves, places) are never shipped; tables are keyed by internal ids and route keys.

## Data flow

```text
pokemon.core --snapshot.from_core--> snapshot --detect.diff(prev own state, cfg)--> new own state + facts
own state  -> fb.run.setState        facts -> events.from_facts -> fb.run.event (automatic)
user action -> corrections.<kind> -> fb.run.event (manual)
view.view(fb.run.current(), fb.run.states(), fb.run.events(...), cfg) -> UI / run board
```

## Modules

### `model.rules`

`parse(run) -> cfg`, `cfg = { mode = "nuzlocke"|"soullink", mode_set = bool, rules = {flag = bool} }`. Settings are read from `run.settings["uzume.soullink"] = { mode, rules = {...} }`. Unknown keys are ignored, wrong types fall back to the defaults. Without a valid mode: `soullink` with two or more joined participants (status `joined` or missing), else `nuzlocke`. Other functions: `defaults()`, `normalize(x)` (accepts a cfg or flat flags), `to_settings(cfg)`, `joined_count(run)`, `DEFAULTS`, `ORDER`.

Defaults: `first_encounter_only` true, `dupes_clause` true, `shiny_clause` true, `hordes_count` false, `pairs_differ_primary_type` false, `only_linked_in_team` false, `nickname_required` true, `level_caps` true.

### `data.oras`

Place keys: `starter`, `loc:<location name id>` (an encounter area of the game, from `areas()`), `place:<text>` (free text, 48 characters) and the legacy `route-101`..`route-134` of runs started before 0.4.0 (still read, label "Route N", never offered again; there is no route list in the plugin). Functions: `area_key(id)`, `area_id(key)`, `is_route(key)` (area or legacy), `is_key(key)`, `custom_key(text)`, `route_number(key)` (legacy), `order_index(key, order)` / `compare(a, b, order)` (starter, legacy routes, areas in game order from `order`, free places last), `label(key, tr, names)` (stored name of the area from `names.loc`, else "Area <id>"; `route`, `route_starter`; free places keep the typed text). `ZONES` (alias `ZONE_TO_ROUTE`, empty) is the fallback for a core without a location id, `COORDS[map id][key] = { x, y, area? }` (empty), `LEVEL_CAPS[badges]` (marked verify locally), `level_cap(badges)`.

### `model.state`

`new(game)`, `ensure(st)` (optional `zones = { ["<zone id>"] = place key | false }`, learned zone answers for the zone fallback, at most 120), `note_name(st, kind, id, name)` (kind `sp` | `loc`; names are cut to 24 / 32 characters, at most 400 / 200 entries, unchanged names report false), `size(st)`, `guard(st) -> ok, bytes`, `compact(st)` (gone mons, then names nothing refers to, then shorter nicknames), `deaths(mon)`, `MAX_BYTES` (48 KiB soft limit, platform limit is 64 KiB). Test: 6 team + 120 box mons with species names are about 22 KiB.

### `model.detect`

- `diff(prev, snap, cfg, opts) -> new_state, facts`. `prev` is never modified. `opts`: `overrides` / `excluded` (from `corrections.route_overrides`, see below; nil = none), `family(species)` (default identity), `areas` (`{ set, order, names }` from `areas()`; nil while not ready), `areas_unsupported`, `zones` (fallback table), `names.species(id)`, `types(species, form)`, `partner_types(route)`, `first` (`auto`|`baseline`|`starter`), `game`.
- `set_place(prev, input, name, zone, loc) -> new_state, fact|nil`: manual place; `input` is a place key or free text (becomes `place:<text>`), empty clears; `zone` / `loc` (what the core reports right now) are stored with it.

Rules of the diff:

- Tracking starts with the first snapshot where team and boxes are both known. Then everything present is baseline, except `first = "starter"` or `auto` with exactly one non-egg mon in the team and none in the boxes: that mon is the starter on `starter`. Encounters up to the newest `seq` at that moment are baseline too (`enc_seq`).
- A personality that is not in the baseline and not tracked is a catch. Its place is the one pending encounter (a route whose entry is still `encounter`), else the current place (`place.key`).
- Egg: gift (`gift`, no route consumed). No place: recorded with route nil, fact `why = "no_place"` (the UI asks). Shiny with `shiny_clause`: `why = "shiny"`, route stays open. Dupe (`dupes_clause`, `family(species)` equals that of a tracked mon that is not dupe/extra/gone): `why = "dupe"`, route stays open. Same primary type as a partner's creature on that route with `pairs_differ_primary_type` (needs `opts.types` and `opts.partner_types`; the partners' types are the `ty` of their counted mons): `why = "type"`, route stays open (not for the starter). Route already used with `first_encounter_only`: kept, `why = "extra"`; with the rule off: `why = "additional"`. A `missed` route whose entry species equals the caught species is upgraded to caught.
- Evolution: same personality, other species: fact `evolve`, mon updated. Form/level/nickname are updated.
- Death: a tracked mon's party/box record itself shows hp 0 (live stats, `max_hp` absent or > 0) in a settled snapshot: no battle is active and none ended since the previous snapshot. The battle's `own` data is never used (it can be stale while a battle ends); while unsettled the last known hp stays so the death is still counted afterwards. Needs known hp before (>0); unknown hp never produces a death. A mon missing from a snapshot with team and boxes both known is `gone` after two consecutive snapshots.
- Encounters: `snap.encounters` entries with `seq` newer than `enc_seq` are new wild encounters, oldest first. Route = a manual place, else the area of the entry's `location` (if it is an encounter area), else the current place. Hordes only count with `hordes_count` (`why = "horde"`), shiny (`shiny`), dupes (`dupe`), partner type (`type`), route already used (`used`) do not count; otherwise route entry `encounter`. Without `seq` in the entries (older shape) every entry is new, and without any list a `battle` start (active, wild) is the encounter. A wild battle that ends does not decide anything: the route stays `encounter` and `pend = { since?, zone?, loc? }` is set. The mon showing up in the party or boxes makes it `caught` (the catch lands on that route; the Pokedex page and nickname dialog come first). The encounter becomes `missed` (fact `missed`) when the location changes (known location id, else zone, compared with the battle's), when the next wild battle or `encounters()` entry starts, or after `PENDING_MS` (60 s, `opts.now` in ms from the caller).
- Place: with a location name id in `location()` and `areas`, the place is `loc:<id>` when the location is an encounter area; a location without encounter slots (town) has no key (`no encounters here`). While `areas` is not ready the place is left alone. Without a location id (or when `areas()` is unsupported) the zone table decides: a mapped zone sets the place, an unmapped zone leaves the key empty and the UI asks (zone learning, fallback only). A manual place wins while its anchor (location id, else zone) stays the same and is replaced when it changes.
- `places` (every place of the game in game order, from `locations()`, at most 600; deduplicated by location id) and `areas` (the encounter areas among them, at most 400) are written to the state for ordering and for the place select; species and place names are stored with each catch / encounter / place and for every tracked mon (`names`). `locations()` is optional: `has_encounters` makes a place an encounter area even when `areas()` lacks it, a place without encounters (town, cave) is selectable but gets no route key. A reading without a key and without a name (name text still loading, `location` nil) is transient: the last known place stays and no `place` fact is produced; a `place` fact needs a new identity (route key, else location id, else name).

Facts (`kind`): `place {key?, name?, zone?, loc?, manual, previous?}`, `catch {mon, species, species_name?, form?, nickname?, level?, shiny, route?, where, counts, why?, gift?, starter?}`, `evolve {mon, from, to, route?}`, `death {mon, species, species_name?, nickname?, route?, deaths}`, `moved {mon, from, to}`, `encounter {route?, species?, species_name?, form?, shiny, horde, counts, why?}`, `missed {route, species?}`.

### `model.snapshot`

`collect(call) -> snap, issues`, `from_core(fb)`. Snapshot (pokemon-core v0.3 shapes): `team` (records with live `level`, `hp`, `max_hp`, `species_name`), `boxes` (list of lists, or flat list), `location {zone?, location?, name?}`, `battle {active, kind, wild (derived from kind), horde?, foes, own}`, `encounters` (list of `{seq, species, form?, shiny?, horde?, zone?, location?}`), `badges` (number, `{count, flags}` or list of booleans). A part that is unsupported, not ready or raising an error stays nil and is listed in `issues`.

### Own state (`model.state`, written with `fb.run.setState`)

```text
{ v = 1, started = bool, inb = bool,
  game = { id, language },
  place = { key?, name?, zone?, loc?, manual },
  baseline = { ["<hex8 personality>"] = true },
  mons = { ["<hex8>"] = { species, form?, nickname?, nicknamed? (false only), level, shiny? (true only),
           route?, where = "team"|"box"|"gone", deaths? (absent = 0), hp?, mhp? (max hp), gift? (true only),
           why? = "extra"|"dupe"|"shiny"|"additional"|"gift"|"type", miss?, ty? (primary type id) } },
  routes = { [route key] = { status = "encounter"|"caught"|"missed", mon?, species?, kind? = "wild"|"horde"|"starter"|"gift", rs? } },
  order = { "<hex8>", ... }, badges = n,
  names = { sp = { ["<species id>"] = name }, loc = { ["<location id>"] = name } },
  areas = { <location id>, ... }, places = { <location id>, ... }, pend? = { since?, zone?, loc? },
  enc_seq = n, zones? }
```

Place keys: `starter`, `loc:<location id>`, `place:<text>`, legacy `route-101`..`route-134`. A mon counts when `routes[mon.route].mon` is its id. `rs` (reset stamp, 0.6.2): seq of the route correction that was in effect when the entry was created; absent in states of 0.6.1 and older (= 0).

### `model.events`

Automatic run events (spec `{type, payload, source = "automatic"}`; `text` is added by the caller with i18n and names read from the game): `soullink.catch {user, mon, species, form?, nickname?, level?, shiny?, route?, counts, why?, gift?, starter?, where}`, `soullink.death {user, mon, species, nickname?, route?, deaths}`, `soullink.encounter {user, outcome = "seen"|"missed", route?, species?, form?, shiny?, horde?, counts, why?}`, `soullink.place {user, route?, name?, manual}`. `from_fact(fact, user)`, `from_facts(facts, user)`. The event order (seq) gives the completion order of link groups.

### `model.corrections`

Event type `soullink.correction`, `source = "manual"`, payload at most 4 KiB. `payload.user` is the player the correction is about; the author is the event's `user_id`. Builders return `{type, source, payload}`, `validate(payload)` / `validate_spec(spec)` return `true` or `false, reason`.

| Kind | Payload | Effect in the view |
|---|---|---|
| `doesnt_count` | `user, route?, mon?, reason? = dupe|shiny|wrong` | mon stops counting, route reopens; without mon: reopens an `encounter`/`missed` route |
| `undo_death` | `group, undone = [{owner, mon, deaths}], reason?` | records per mon the death count that is undone (`undo_entries(group)` from a view group); revives the group |
| `set_group` | `user, mon, group = route key | "none"` | moves the mon into that route's group (also assigns a catch that had no place); `none` = no link |
| `add` | `user, route, species, form?, nickname?, level?, shiny?, state = team|box|dead` | hand-added mon (id `add-<seq>`), replaces missed/open; extra when the route is taken |
| `mark_missed` | `user, route` | route is missed for that player |
| `mark_dead` | `user, mon, reason?` | one more death |
| `set_gift` | `user, mon, gift = bool` | gift: group state `gift`, no link |
| `revert` | `target = seq, reason?` | cancels the correction event `target`; a reverted revert cancels nothing |

**Corrections and detection (0.6.2).** The own state is never rewritten by a correction. Instead `corrections.effective(events)` (valid corrections in seq order, reverts applied) and `corrections.route_overrides(effective, user, st) -> overrides, excluded` describe what the corrections do to one player's routes: `overrides[route] = { kind = "reopen"|"missed"|"taken", seq, mon? }` (`doesnt_count` reopens a route or the route of an excluded mon, `mark_missed` closes a route that no counted mon holds, `add` lets the hand-added mon `add-<seq>` hold a free route) and `excluded[mon]` (mons that no longer count). A route entry whose `rs` is below the override's seq predates the correction and is shadowed by it; an entry created later (detection stamps `rs = override seq`) is valid. A correction therefore applies to what happened before it; a later encounter on a reopened route is the first one. The view (`cell_state`, `assign_slots`) and detection (`detect.live_entry`: encounters, catches, the pending encounter, missed expiry, the dupes check) both use the same overrides; the controller computes them from the cached events for its own user (any author) before every `detect.diff`. Reverting a correction removes its override, so the stored entry is visible again; if a new entry replaced the old one in between, the old one is gone (open point).

### `model.view`

`view(run_current, states_by_user, events_in_seq_order, cfg) -> view`. Pure and deterministic. Players are the participants with status `joined` (without participants: the keys of the states).

- `names` (`{ sp, loc }`, merged from all states, own first), `areas` (location ids in game order, merged), `order` (area key -> position).
- `players[i]`: `id, name, color, game_id, place {key, name, zone, loc, manual, status}`, `team` (list of mons, team order), `box_count`, `alive`, `dead`, `badges`, `level_cap`, `mons` (id -> mon), `ids`. `place.status`: `unknown`, `no_route`, `open`, `encounter`, `caught`, `missed`.
- mon: `id, owner, species, species_name (stored name, nil = show #id), ty, form, nickname, nicknamed, level, shiny, hp, route, where, dead, cause ("own"|"linked"), doa, deaths, gift, why, excluded, virtual, counted, group, group_state, group_number`.
- `rows` (routes with activity, route order): `{route, order, cells = {user -> {state = open|encounter|caught|missed|dead, mon?, species?, nickname?, gift?, cause?}}, group, done}`.
- `groups` (SoulLink only), numbered first, then by route order: `{route, state, number?, complete, count, members = [{owner, id, species, nickname, deaths, dead, cause, doa}], died_seq?, completed_seq?}`. States: `linked` (all players caught, alive), `open` (pending), `dead` (some member died; also while pending), `broken` (someone missed, no link, no propagation), `gift`, `nolink`. Numbers 1..n go to complete `linked`/`dead` groups in the order of `completed_seq` (the largest catch or placement event seq of the members); without event seqs the route order decides.
- Deaths: a mon is dead when its deaths (detected + `mark_dead`) exceed the undone count. A dead member kills its group (`cause = "linked"`); a mon caught into an already dead group is dead on arrival (`doa`, needs the catch event seq).
- `graveyard`: dead mons ordered by death seq (own death event, or the group's first), then player, then id.
- `stats`: `deaths, groups_dead, groups_linked, routes_done, routes_total (starter + areas + free places and legacy routes with activity), badges_max, alive`.
- `hints` (never blocking): `nickname_missing`, `level_cap {level, cap}`, `unlinked_in_team`, `partner_not_in_team {partner, partner_mon}`, `type_clash` (same primary type in a link group with `pairs_differ_primary_type`); each with `user, mon`.
- `invalid_corrections`: seqs of correction events that failed validation (ignored).
- `zones`: `merge_zones(run, states)` -> zone id (integer) -> route key | `false`: static `oras.ZONES`, then the own state's `zones` (`run.me`), then the other players' in user id order; the first entry for a zone wins.
- Nuzlocke mode: no groups, deaths stay with the owner.

## Wiring (`app.controller`)

- Without `fb.run` (game not started from Runs, or shell context without an open run): panel, HUD and screen show an empty state ("Start this game from Runs → Play run"; the screen text also points to the Runs page), no core calls, no tracking.
- Core parts that answer "unsupported" (`snapshot` option `unsupported`) are not asked again.
- Run view (`fb.run.current().view == true`, shell context, read only): the controller sets the `run` slot with the run screen builder (`screen.build` with `readonly`: routes, team & box, graveyard, event log; no correction forms or write buttons) and the screen slot shows the Runs pointer. No core calls, no polling, no notices, no board, no `tiles` subscription, no own state injected. Every write action is ignored; the platform would answer `setState`/`event`/`setBoard` with `nil, "read only outside the game"`. `common.writable` is false for a run with `view`.
- With `fb.run`: own state is continued from `fb.run.state()`. Every 500 ms: `snapshot.from_core` (team, location, battle, encounters, badges; boxes every 5 s, in between the last box read is reused), `detect.diff`, `setState` only when the encoded state changed, facts posted as automatic events (text from i18n with species and area names read from the game; `#<id>` only while no name is known). Core calls are `pcall`ed; failures are logged once. Paused/finished/abandoned runs are read only: no polling, no writes, banner in the panel, no action buttons.
- Subscriptions: `fb.run.on` for `event`, `state`, `participants`, `status` (4 of 16), host event `tiles`, `fb.ui.on_action`. Events are cached (paged from seq 0), the view is recomputed at most every 250 ms when something changed.
- `app.sync.push(slot, tree)`: unchanged tree = nothing, same structure with changed props on blocks with an id (at most 12) = `fb.ui.patch`, else `fb.ui.set`.
- Board: `fb.run.setBoard` with the compact tree (players, routes table, graveyard, deaths), at most every 5 s and only when it changed.
- Notices (`fb.ui.notify`): deaths in the own link groups (important, actions "Open run" and "Undo death...", HUD expanded for 3 s), catches of others that count (info), new route hint for detected places (info). A death waits for the state that shows it (up to 40 renders).
- Hotkeys: `toggle-hud` does nothing (the host handles it), `doesnt-count` opens the 5f-1 form for the current route, `open-run` (Ctrl+R) opens the run screen.
- Open the run screen: `open_run` (panel buttons, toast action, Ctrl+R) calls `fb.ui.open("screen")` through `pcall`, only when `fb.ui.open` exists (the platform shows the screen slot as a dark sheet over the game; out of game the slot is the plugin tab in the run view, the "run tab"). Without it the panel shows "Update Uzume to open the run screen" instead of the two buttons. There is no run view inside the panel any more.
- Names and areas (`app.controller`): `areas()` is read once when ready (`unsupported` = zone fallback); `name("species"|"location", id)` results are cached (at most 16 lookups per poll, `not_ready` is retried); `species_info` only when `pairs_differ_primary_type` is on. The detection stores the names it uses in the own state (`names`), the view merges them from all states, so other players, the HUD, the tile strip and the Runs page show names without a game. Live area names win over stored ones in the own UI.
- Badges come from `badges()`; the badge select in the panel footer appears only while the core has not delivered badges. The place picker appears only while the core reports no location (collapsed behind "Set place"; the "which place is this?" card for an unmapped zone is the fallback for a core with zone but no location id).
- Icons (`app.icons`): builders call `ctx.icon(species, form)` -> `cache:icons/<species>-<form>.png` or nil (queued once). At most 3 `pokemon.core` `icon` calls per tick, after `info().features.icons` is true (re-checked every 10 s while false; unknown `info` just tries). `nil, "not_ready"` is retried after 5 s, 10 s, ... up to 30 s; any other failure is remembered per creature; five failures without a success switch icons off. Used as `image` blocks in team rows (panel, screen), list rows (graveyard, box, panel graveyard), the selected route and map marker `icons`.
- Route detection: each poll passes `areas`, name and type resolvers and the merged zone table to `detect.diff` and remembers the reported zone and location (`cur_zone`, `cur_loc`). Only without a location id (zone fallback): an unmapped zone shows the card "New place detected" (place select, free text, "Not a route"); the answer is stored in the own state `zones["<zone>"]` unless the static table or another player's mapping covers the zone, and reaches every player through the merged table. Without `location()` support at all: the manual picker.
- Map (`app.maps`): the player opens the in-game map on the 3DS bottom screen and presses "Take map from screen" (action `map_capture`): `fb.video.screens()` decides the target (`bottom`, else `main`), `fb.video.capture(target)` returns a request id and the host event `video.captured` `{ id, ok, png, w, h, error }` (subscribed only when `fb.video` exists and not in the run view) delivers the PNG. Success writes `map/<game id>.png` (game id = `fb.game.code`) and `map/current.txt` in the own cache (the map is never part of the run state); failure shows the localized text `map_err_<code>` (`busy`, `rate_limited`, `no_frame`, `unknown_screen`, `invalid_rect`, `too_large`, `unsupported`, `denied`, other = `failed`). The game is not paused during the capture. Without `fb.video` (older app) the Map tab shows the update hint and nothing else changes; in the shell run view no capture is offered. Route positions: `oras.COORDS[game id]` under the player's recorded ones in `map/coords.json` (`{"map":game id,"routes":{key:{"x","y"}}}`, keys `loc:<id>`). "Retake map" replaces the image and keeps the positions, "Remove map" (with confirmation) writes an empty `map/<game id>.png` and keeps the positions. Calibration (button "Place routes", also available in a paused run, cache only): place select (`common.place_options`: every place from `locations()` incl. towns and caves, `areas()`, places used in the run and the players' current places, no starter; the current place of this player is preselected; with none known the select holds one localized hint "No places from the game yet"; up to 100 places in one select; with more, a group select in front (`calib-group`, segmented for <= 3 groups, action `calib_group`) lists "Places a-b" groups of 90 in game order, the first group also holds the places used in the run and the current places; the place select shows the group of the selected place), step 2/10/40 px, arrows, "Set position" (marker id `cursor`), "Export positions" logs one line `COORDS["<id>"] = { ["loc:301"] = { x = .., y = .. }, ... }` with `fb.log.info`. Manifest permission `video.capture`. Crop (0.5.1): `fb.video.capture` gets a rectangle inside the `bottom` (else `main`) entry of `fb.video.screens()` (`maps.crop_rect`), so the stored PNG is already cropped. The crop is four whole percents (top/bottom/left/right, each 0..45, opposite sides below 90) edited with the buttons -5/-1/+1/+5 and the presets "Full screen" (`crop_toggle`, `crop_adj` value `t:-5`, `crop_preset`); "Retake with this crop" takes the map again (the game has to show the map). The crop of the stored image is saved in `map/coords.json` as `crop = { t, b, l, r }`; the default crop is the full screen (0.5.1 to 0.5.x estimated one for ORAS; it cut the map and was removed). Positions are image pixels of the cropped map: a retake with another crop RESCALES them (same point on the game screen, clamped to the new image) instead of clearing them; after "Remove map" and a restart the old size is unknown, so positions are then kept as they are. Open: whether the captured bottom screen shows the full map without UI frame depends on the map the player opens; positions recorded on one capture size may be off after a retake at a different size.

## UI

All strings come from `plugin/i18n/en.json` (source) and `de.json`; only tones, sizes and player numbers (participant color + 1) are used. Death is shown as a grey `✕` prefix, never red.

- Panel (5b), built for about 300 px, top to bottom: run header (run name, quiet "Open run" with action `open_run`, the only button that opens the run; read-only badge when paused/finished; no eyebrow, the app draws "Drawn by SoulLink"); `location` block; "Set place" link and picker only when the core cannot report a location; encounter card (eyebrow "Encounter now", icon, "Wild <species>", meta "first on this route", quiet "Doesn't count" with the manifest key hint `Ctrl+D`, which opens the 5f-1 form inside the panel, the only correction form the panel shows); "Your team · n / 6" rows (icon, nickname + level, species name, HP bar, "Linked with" eyebrow and at most two partner icons, "+n" for more); graveyard chip (collapsed; opens a list of at most 10); footer "Graveyard n · Badges n / 8 · next cap Lv n" (the 8 is `oras.BADGES`; the cap only when known; badge select only while the core has no badges). Without `fb.ui.open` the footer says "Update Uzume to open the run screen". No tabs, map, stats grid or filter chips.
- HUD (5b-2): one `card` (action `hud_toggle`): text "SL · <place>" and a `badge` with the toned status. Expanded (click) or for 3 s after a linked death: other players with their state on the same place.
- Tile (5d): `tiles` host event (`{ id, player, user_id, game }`) matched to participants by `user_id` first, by name (case-insensitive) as fallback; strip text `SL <place> · <n> alive`.
- Screen (5e, `screen` slot; read only in the `run` slot of the Runs page): summary eyebrow "Deaths n · Routes a / b · Badges n" (a warning badge when the run is read only), correction section, `tabs`: Map | Routes | Team & box | Graveyard | Event log (plain names; the selection is kept by tab id; the Map tab leads only when a map is stored, see the Map tab below), then the foot: one-line rules summary with a "Show rules" chip (read-only list in a short `scroll` area) and the "Game data" chip (diagnostics stay closed until opened). Map tab: source eyebrow ("Map from your game file" / "game picture"), map block with route card `popover` rows (person, icon, state) for the selected route, buttons "Place routes", "Retake map", "Remove map", calibration; before a map exists the empty state, source chips and the chooser. Graveyard: clusters per link group (eyebrow, rows with image, species/level, owner, place, cause and the death time, "Undo…"). Event log: chips All / Automatic / Manual · n, a people select (action `log_person`), newest 100 rows with the event time (UTC) as meta and the kind in the sub line; manual rows warning tone, correction rows revert.

Danger/confirm dialogs on the buttons for undo death, mark dead, mark missed and revert. ## Open points

- pokemon-core 0.3 shapes are taken from `notes/pokemon-research/core-interface-v03.md` (location `{zone, location, name}`, `areas()`, `encounters()` with `seq`, `battle().own`, `badges()`, `name()`, `species_info()`); checked against the fake core only. Box numbering base of `box(n)` (assumed 1..`box_count()`) is still open.
- Family lookup (evolution lines) for the dupes clause: only the `family` hook exists, the default compares species ids. A table keyed by species ids is needed (no names).
- The type rule is a re-roll clause like the dupes clause (`why = "type"`); it needs the partner to have caught on that area first and `species_info` to answer. Whether a late type clash should instead be a hint only is a rules question.
- Death from `battle().own` while the party data still shows the old hp: if the party hp never drops to 0 after the battle (item, revive), a later faint can count a second time.
- Route selects show at most 100 options (block limit); areas at the end of the game order are dropped first, keys with activity stay. A paged picker is not built.
- ORAS level caps (`data.oras.LEVEL_CAPS`) and map positions (`COORDS`, via "Place routes" and its export line) are to be filled and verified locally with the real game.
- Changing rules during a run is not modeled (run settings are fixed at the start).
- Tracking start (baseline vs starter) is decided from the first snapshot; the run start flow should tell the plugin explicitly (`opts.first`).
- Participants with status other than `joined` are not players; `left` participants drop out of link groups.
- Broken groups (someone missed) do not link the remaining members at all; whether partners that caught should stay linked is a rules question for the design.
- `fb.ui.open` is assumed as briefed (`fb.ui.open(slot)`, platform 0.11+): its return value and error cases are not documented; it is called through `pcall` and a failure only logs once.
- Text fields only report their value on Enter, so the correction forms say so; a form submit button cannot read unsent text.
- Approval of corrections by another player and the settings page (5i) are not built; the run start (5a) is the platform's Start dialog with the manifest rules section.
- Map from the game files (0.6.0, `app.maps`): the Map tab shows a source switch (chips `map_src:screen` / `map_src:files`) when both sources exist; the choice is `ui.map_src`, else the source of the stored map. `maps:files_step(now)` runs every tick (not in the run view): `fb.call("pokemon.core", "map_candidates")` every 3 s until it returns a list (`nil, "not_ready"` = still scanning; shown as "Still searching the game files"; the core gives no progress, so there is no count before the list); up to 40 entries `{ id, w, h }`; `map_selected()` is asked once and its id is marked as suggested. A call error or `unsupported` turns the option off for good (no chip, no section). The shown candidate (`idx`, "Image n of N", actions `map_prev` / `map_next`, wrapping) gets its preview with `map_image(id)` (`nil, "not_ready"` is retried after 2 s, any other failure marks the image as not shown), stored as `map/cand-<idx>.png` and shown as `image` `cache:map/cand-<idx>.png`. "Use this map" (`map_use`) writes the PNG to `map/<game id>.png` (and `map/current.txt`) like a capture, sets crop 0, rescales the recorded positions from the old image (screen fraction kept), and records `"source":"files","file":"<candidate id>"` in `map/coords.json` (omitted for a captured map). A capture sets the source back to the screen; "Remove map" drops the source and keeps the positions. Without `fb.video` the files source is the only one; in the shell run view no core call is made. Open: no scan progress from the core; candidate ids are only stable while the game files do not change.
- Core lists (0.5.1): `areas()` and `locations()` are asked again (`A:ask_list`) on `nil, "not_ready"|"failed"` (2 s before the first list, then 5 s), on an empty list and on entries without a name; only a non-empty, fully named list is final and is refreshed every 30 s (the info is rebuilt when it changed). `unsupported` stays permanent. pokemon-core 0.3.2 entries with `source = "text"` (no zones, no encounters) are ordinary places.
- Game data (0.5.1): the controller asks `pokemon.core` `diagnostics()` (pokemon-core >= 0.3.2, optional; a flat table of numbers/strings/booleans, shown as sorted `key=value` text under the title "Game data", one wrapped line per key group = the text before the first `_` (every key is shown), with a hint to send a screenshot; 0.6.0) once to learn whether it exists, then every 5 s while the place list is empty or the block is open. The run screen header has a chip (`diag_toggle`, "Hide game data" / "Show game data") only when the core answered; the block is closed by default and opened with the chip (`ui.diag_open == true`, kept across refreshes; 0.6.1); the Routes tab shows the block by itself while `view.places` is empty and the header block is closed. A core without `diagnostics()` ("unsupported") means no chip and no block.
- Icon check (0.6.2): while the Game data block is open the controller asks `pokemon.core` `icon_variants(species, form?)` (pokemon-core >= 0.3.4, optional) once per opening for the first creature of the team as the core reports it (`nil, "not_ready"` is retried every 5 s, `unsupported` switches it off for good). Up to 4 `{ label = "A".."D", desc, png }` entries are written to the cache as `diag/icon-<label>.png` and shown in a row inside the block (`image` size `m`, label and description under each, hint "Tell us which picture looks right"). Without the function the section is absent. Open: the cache file names are reused between openings, so the host must reload a changed file of the same name.
- Corrections that move a mon (`set_group`) do not reopen the route the mon was detected on; detection still treats that route as used.
- Release: the `.uzplugin` is unsigned; signing and the server upload flow are open. Requires pokemon-core `>=0.3.1` (`locations()` is used when answered, the plugin also works without it); version 0.4.1 of this plugin.
